## ФОРМАТ ПРАВОК КОДА — патчер (единственный разрешённый способ)

Правки файлов проекта — только python-патчером (не «руками» в редакторе, не sed по памяти). Патчер — отдельный файл `/home/user/work/patch-stepN-<имя>.py` и содержит:

- (a) страж идемпотентности = характерная фраза САМОГО вставляемого блока (не заголовок раздела);
- (b) правило пропуска: `if new_block in src: skip` — НЕ «старого текста нет» (при вставке после якоря новый блок содержит старый целиком, и такая проверка всегда врёт);
- (c) `assert src.count(old) == 1` перед заменой;
- (d) бэкап `*.bak.<UTC>Z` + атомарная запись (`.tmp` + `os.replace`);
- (e) сохранение режима файла: `os.chmod(tmp, mode)` ДО `os.replace` — критично для 755-скриптов `scripts/*.py` (снапшот и сам патчер могут сбросить +x, а ruff EXE упадёт);
- (f) самопроверка ПОСЛЕ записи: дословный подсчёт вхождений нового блока (ожидаем ровно 1).

Локальная проверка патчера: `ast.parse` + CJK-аудит (regex `r"[\u3040-\u30ff\u3400-\u4dbf\u4e00-\u9fff]"` — 0 совпадений) + сухой прогон на md5-копиях целевых файлов ДВАЖДЫ (второй прогон обязан всё пропустить — это проверка идемпотентности).

Применение: `python3 /home/user/work/patch-stepN-<имя>.py` в песочнице; целевые пути — только из «КАРТЫ РЕПОЗИТОРИЯ».

Проверка после: `python3 -m py_compile <файлы>`, `grep -c '<фраза-страж>' <файл>` (=1), `wc -l`, режим файла (`ls -l`), P1–P5.

Дальше: тесты (все профили) → доки → git (+пуш) → NOTES-stepN.md.

Для JSON (схемы, каталоги, state) править загрузкой/модификацией/выгрузкой: `json.load → … → json.dump(indent=…, ensure_ascii=False)` — НЕ текстовой заменой.

## ЖЁСТКИЕ УРОКИ ЭТОГО ПРОЕКТА

Общие (не вычёркивать):
1. «Файл изменён» ≠ «изменён один раз»: патчер, упавший на верификации ПОСЛЕ записей, удваивает блоки. Спасает только дословный подсчёт вхождений.
2. md5-сверка: «пусто == пусто» даёт ложное ✅ — требовать непустых хешей с обеих сторон и `sys.exit(1)`.
3. Числа и пути — только из свежей команды; `ls -t` для журналов врёт на пустом месте — сортировать по имени, считать явно (`| wc -l`).
4. «Последний отчёт» ≠ «последний прогон»: писать отчёт на каждом выходе с явным outcome.
5. Пустой результат бывает по разным причинам («нечего делать» vs «отказались считать») — в отчёте это разные исходы.
6. CJK-утечки ловить `r"[\u3040-\u30ff\u3400-\u4dbf\u4e00-\u9fff]"`; `\u`-эскейп в docstring ломает файл (unicodeescape) — строки с обратными слэшами писать raw.
7. `None` в списке строк проверять ДО `.strip()`; результат `re.search` — ДО `.start()`.
8. Числа в доках стареют мгновенно: после каждой правки пересчитывать строки/md5/счётчики командами.
9. Интерпретатор имеет значение: в каноне — один канонический интерпретатор (`/usr/local/bin/python3`).
10. `.git/config` не переживает снапшот: «пропавший origin» — штат; лечится командой стартера, токен не печатать.
11. Окружение не переживает снапшот: пакеты пересоздавать каждую сессию по lock; фиксировать версии выводом `pip show`.
12. Снапшот не резиновый: репозиторий держать компактным, мусор — в `.gitignore`.
